# Delegation Creep implementation note

This illustrative process model treats one context as one task opportunity and requires a task domain, consequence score in `[0, 1]`, and an explicit review flag with its approval value. A task is an expansion opportunity when its domain has not previously received delegation or its consequence is at least `0.5`. The state carries the delegated-domain history, prior opportunity count, prior reviewed-and-approved delegations, and cumulative delegated workload, so the effect depends on an actual chronological sequence.

The explicit strength-zero reference delegates a full task-equivalent exactly when suitability was reviewed and approved; otherwise it delegates zero. For an unreviewed expansion, the model allocates a fractional share `strength × prior_approved_delegations / prior_total_opportunities` (zero when no prior opportunities exist). Reviewed approved tasks still follow the reference policy. The returned primary metric is cumulative delegated task-equivalents; the state separately records unreviewed expansion workload. Strength is a user-set illustrative setting, not a calibrated effect size.

The positive scenario first establishes two reviewed, approved scheduling delegations and then presents an unreviewed consequential task in a new domain. At strength `0.8`, that final task adds `0.8` task-equivalents versus the zero-strength reference. The boundary scenario has an affirmative suitability review, removing the necessary unreviewed condition; both policies therefore produce the same metric. An unreviewed, low-consequence task in an already delegated domain also has no modeled creep effect.

The model assumes a simplified reliance-momentum allocation process, fixed structured task-domain labels, a consequence threshold, and fractional workload. It neither identifies real-world suitability nor infers motives, and it omits organizational controls, task outcomes, and richer review quality. It is explicitly hypothetical and synthetic, not empirically validated; software tests check the implementation only, not psychological validity or detection accuracy.
