# Fear appeal implementation note

This illustrative plugin models a narrow media practice: a supplied message uses explicit threat/disaster language while stating a probability above the provided evidence-supported probability, and the reader is assigned extra precautionary action. It is a structured process model, not a language detector, diagnosis, population claim, or empirically validated psychology.

For each exposure, the stipulated strength-zero reference rule allocates action as `severity × evidence_supported_probability × response_capacity`. If `threat_language` is true, the hypothetical unsupported-urgency term is `threat_salience × max(0, stated_probability − evidence_supported_probability)`; otherwise it is zero. The per-step metric is reference action plus `strength × severity × response_capacity × unsupported_urgency`. Its units are illustrative normalized precaution points (at most 2 per step, not a calibrated scale). State preserves prior fields and records the last action, cumulative points, and step count.

Inputs are explicit synthetic values in [0,1]; `threat_language` must be boolean. The necessary concept conditions are explicit threat/disaster language, positive threat salience, and a positive stated-versus-supported probability gap; without any of these there is no mechanism effect. The positive scenario uses severity .9, salience .8, stated probability .7, supported probability .2, and capacity .75. It gives reference action .135 and action .351 at strength .8. The boundary scenario retains threat language but makes the probabilities equal (.2), so its metric equals the reference at all strengths.

All coefficients and field interpretations are user-settable assumptions, not published effect sizes. Evidence adequacy, severity, probabilities, salience, reader capacity, and action response are accepted rather than verified. Real urgent risk communication can be accurate, useful, and protective; this model only illustrates excess action under its supplied mismatch condition. Passing software tests does not constitute empirical validation.
