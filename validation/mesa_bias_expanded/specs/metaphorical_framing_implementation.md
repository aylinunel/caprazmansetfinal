# Metaphorical framing implementation

This plugin models a structured reader task, not metaphor detection. For interpretation option *i*, its choice score is `(1 − strength) × literal_support_i + strength × alignment_i`, where `alignment_i = 1` only when the option's supplied event relation exactly matches the metaphor's explicitly supplied mapped event relation; otherwise it is `0`. The deterministic choice is the highest score (ties break by option ID). The returned metric is the selected interpretation's supplied `response_priority`, a unitless value from 0 to 1. The state records the selected interpretation, metric, current frame activity, and chronological history.

The strength-zero reference policy selects the option with the greatest supplied literal support. The necessary concept condition is an explicit, nonempty source-schema-to-event-relation mapping and an available interpretation matching that mapped relation; with no metaphor supplied, structural alignment is zero for all options. The positive example maps a bridge closure onto a “siege”/defensive-conflict relation, shifting selection from routine maintenance to system-under-siege at strength 0.8. The boundary example removes the metaphor and therefore matches the literal-support reference.

All evidence and coefficients are synthetic structured inputs. The module does not analyze text, assess author intent, or imply that metaphor use is an error: a frame could clarify, obscure, or simply redirect understanding. The concept specification supplies no annotation boundary or empirical parameters, and this toy task is neither empirically validated nor representative of reader behavior.
