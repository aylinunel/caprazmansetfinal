# Google Effect implementation note

This is an explicitly hypothetical, synthetic study-and-recall process model; it is not empirically validated and is not an NLP detector. Each study event adds a memory signal for an item with supplied difficulty `d` in `[0,1]`. The strength-zero reference policy adds `1/(1+d)` regardless of external access. At strength `s`, explicit expectation of later external access changes this to `(1/(1+d)) * (1 - 0.60s)`. Actual lookup use is recorded but does not itself change encoding. Repeated study events accumulate signal. A chronological retrieval event reports `1 - exp(-signal)` per previously studied item; the primary metric is the sum of those item recall probabilities (“modeled recall units”).

The necessary condition is an explicit `expected_external_access=True` on the item’s study event. The positive example studies an item with that expectation and then retrieves it, yielding lower modeled recall at strength 0.8 than the unattenuated reference. The boundary example records an external lookup while expectation is false; its retrieval metric must equal the reference at strength 0.8. Lookup is not modeled as inherently erroneous, and reduced internal recall is not equated with faulty reasoning.

Assumptions are the illustrative encoding coefficient (0.60), the supplied difficulty’s simple effect on baseline signal, and the exponential signal-to-recall mapping. These are user-settable modeling choices, not published effect sizes. Limitations include no empirical calibration, no individual differences, forgetting, source quality, actual retrieval process, or distinction between kinds of external aids. Consequently, outputs are suitable only as a compact executable illustration of the supplied operational definition, not as population claims, diagnosis, or a measurement of real people.
