# Category Size Bias implementation note

This illustrative model reports a probability for one explicitly named outcome in a complete, mutually exclusive outcome space. Each supplied outcome has an individual probability and a category. The reference rule (strength 0) reports the focal individual's supplied probability, `p_i`. Category aggregate probability is `P(C_i) = sum(p_j for j in focal category)`. Only when every individual outcome has equal supplied probability does the model interpolate toward treating that aggregate as the chance of the focal individual: `judged_i = (1 - strength) * p_i + strength * P(C_i)`. The metric is the judged probability of the individual outcome, in probability units; the category aggregate is retained separately in state. At strength 0.8, three equally likely members in a five-outcome category (each outcome probability 0.2) yield `0.52` reported probability for a member (`0.2 + 0.8 * (0.6 - 0.2)`).

The necessary modeled condition is equal individual probabilities. The boundary scenario uses unequal individual probabilities, so the category aggregate may legitimately differ from the focal probability but does not substitute for it; the metric remains the reference focal probability at strength 0.8. This preserves the distinction between an individual event and a category event: a larger category can truly have greater aggregate probability, and that aggregate alone is not an error.

Inputs must explicitly enumerate at least two unique outcomes, their nonempty category IDs and finite probabilities in `[0, 1]` summing to one, and the focal outcome ID. Missing evidence is rejected. The process is deterministic and nonmutating, with state recording steps, the latest focal/reference and aggregate probabilities, and whether individual chances were equal.

This is a synthetic, hypothetical process model, not a detector, diagnosis, fitted psychological theory, or empirically validated claim. The supplied probability space and category mapping are assumed correct; the implementation cannot establish how a person would actually judge an outcome, whether categories are psychologically salient, or whether an aggregate probability is what a task asks for. Strength is an illustrative setting, not a measured effect size. The code tests verify implementation behavior, not empirical validity.
