# Bounded Rationality — illustrative implementation

**Process.** The task supplies a finite ordered list of options with utilities, a maximum evaluation capacity, and an optional aspiration threshold. At strength zero, the reference policy inspects every option and chooses the highest-utility option. At strength \(s>0\), the illustrative inspection budget is \(B=\max(1,\min(n,\lfloor n-s(n-C)\rfloor))\), where \(n\) is the number of options and \(C\) is the stated capacity. If that budget binds and a threshold is visible, the choice is the first inspected option whose utility meets the threshold; if none does, or the threshold is absent, the choice is the highest-utility inspected option. This is an assumed process model, not a fitted psychological mechanism.

**Task and units.** Choose among supplied options; the primary metric is utility regret, \(\max_i u_i-u_{chosen}\), in the same arbitrary utility units as the supplied option values. `active` is true exactly when this regret is positive versus the exhaustive maximum reference for the same task.

**Necessary conditions and examples.** The positive scenario includes an explicit resource constraint (capacity 1 for 3 options), ordered options, and an explicit aspiration threshold; at strength 0.8 the first satisfactory option is chosen, with illustrative regret 4. The boundary scenario removes the binding-capacity condition by setting capacity to the full three options; search is exhaustive and regret equals the strength-zero reference (0), even though a threshold is supplied. Missing options, utilities, capacity, or threshold field are not silently treated as zero; `None` explicitly means no aspiration rule.

**Assumptions and limitations.** Option order is inspection order; utilities, resource capacity, and aspiration threshold are known inputs, not inferred from media or text. The linear strength-to-budget interpolation, rounding, and first-satisfactory stopping rule are illustrative user-settable assumptions. A constrained satisficing choice can be adaptive and beneficial, not inherently an error. This module is synthetic and explicitly hypothetical; it is not empirically validated, a classifier, a diagnosis, or an NLP detector. The metric captures task utility loss only and cannot judge whether the objective or threshold is appropriate.
