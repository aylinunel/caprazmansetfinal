# Incentivization implementation note

This is a hypothetical, synthetic-only model of one explicit task decision; it is not an empirical claim or a detector of motivation. For a binary completion choice, intrinsic surplus is `task_value - effort_cost`. The reference policy completes when that surplus is nonnegative. At strength `s` in `[0, 1]`, the model adds `s * (completion_reward + noncompletion_penalty)` and completes iff the resulting effective surplus is nonnegative. `active` is true only when this incentive changes the strength-zero choice. The primary metric is binary task completion (`0` = not completed, `1` = completed).

The positive scenario has intrinsic surplus `2 - 5 = -3`; at strength `.8`, reward and penalty total `4`, adding `3.2` and moving the decision across the threshold. The boundary scenario removes the necessary consequence contingency by setting both reward and penalty to zero, so its metric at `.8` equals the reference metric. No task value, effort cost, or consequence is inferred when absent; required amounts must be supplied and finite nonnegative values.

Assumptions are that inputs share a comparable utility scale, consequences are additive and salient, the choice rule is deterministic, and strength scales only the incentive component. These are illustrative user-settable assumptions, not calibrated effect sizes. The model omits reward crowding-out, fairness, context, timing, learning, and heterogeneous preferences. Incentives are motivational mechanisms, not inherently biases, harmful interventions, or evidence of manipulation; a completion change is not inherently beneficial or harmful. Tests establish software behavior only, not empirical validation.
