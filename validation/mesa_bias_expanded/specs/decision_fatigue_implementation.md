# Decision Fatigue — illustrative implementation

This plugin treats decision fatigue as a hypothetical sequential process, not a detector or diagnosis. Each task supplies at least two options with explicit utility and normalized effort, plus `decision_load` in `[0,1]` for the current decision. Carried load is `L(t+1) = 0.75 × L(t) + decision_load(t)`. On a later decision only, the illustrative fatigue shortcut activates when `strength × L(t) >= 0.60`; it then selects the lowest-effort option. The current choice is compared with the reference policy, which selects the supplied maximum-utility option (input order breaks ties).

The primary metric is **utility regret**, in supplied utility units: `max(option.utility) - chosen.utility`. It is zero for the reference choice and positive when the effort-avoidant shortcut sacrifices supplied utility. `active` indicates that the shortcut changed the choice from the reference on this step. The state returns accumulated load, number of prior decisions, and last choice.

The necessary conditions are explicit decision load carried from prior decisions, an accumulated-load threshold at the selected strength, and an available minimum-effort option different from the maximum-utility option. Time of day alone does not trigger the mechanism. The positive scenario supplies repeated load and a clear utility/effort tradeoff; at strength 0.8 it yields regret on later choices. The boundary scenario removes load, so its metric matches strength zero. Strength zero is the justified reference policy, not a claim of perfect real-world rationality.

Load retention, threshold, and choice shortcut are transparent illustrative assumptions, not published effect sizes or empirically fitted coefficients. Effort-minimization may be adaptive or harmless in real settings; low utility or avoidance cannot be inferred from choices without supplied task facts. The model does not represent fatigue causes, individual variation, or other possible outcomes. The code and tests are synthetic and explicitly **not empirically validated**.
