# Law of the Instrument — illustrative implementation

This module models a structured tool choice, not an NLP detector or a claim about population behavior. A task supplies a nonempty set of required capabilities and a list of tools, each with declared capabilities and familiarity in `[0, 1]`. Tool fit is exact requirement coverage: `coverage = |requirements ∩ capabilities| / |requirements|`. The reference policy selects the tool with maximum coverage (ties use input order). In `transfer` mode, the illustrative score is `(1 − strength) × coverage + strength × familiarity`; in `customary` mode, the score remains coverage regardless of strength. The returned primary metric is the number of task requirements absent from the selected tool, in **count of unmet requirements**.

The necessary condition is explicit cross-context transfer (`application_mode='transfer'`): a familiar tool/skill is considered for a task beyond its customary application, and an inferior-fit familiar option can displace the best-fit option. `customary` marks the annotation boundary—a fixed customary use—and disables familiarity weighting. Strength zero reproduces the best-coverage reference rule. The positive scenario uses a familiar spreadsheet that covers calculation but not visualization against a specialist suite that covers both; at strength 0.8 the model selects the spreadsheet, increasing unmet requirements from 0 to 1. The boundary scenario holds the task and tools constant but marks the application customary, so the strength-0.8 metric equals the reference metric.

All inputs are explicit synthetic scenario facts; missing inputs, malformed capabilities, and out-of-range familiarity values raise `ValueError` rather than being treated as zero evidence. The state records decision count and choice history without affecting the next choice. The familiarity blend, exact matching, linear strength parameter, and tie rule are user-settable illustrative assumptions, not effect estimates. Familiarity can be useful and may proxy for unmodeled fit; the model cannot determine that a real-world choice is an error, establish motive, or generalize beyond the supplied structured task. No empirical validation is claimed.
