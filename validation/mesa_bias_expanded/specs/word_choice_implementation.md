# Word choice: illustrative implementation note

This module models an authored selection among supplied labels for one explicitly identified fact. Each option has a `fact_id`, a hypothetical `factual_fit` in `[0,1]`, and a hypothetical signed `connotation` in `[-1,1]`. It does not inspect or classify text.

**Process and metric.** Restrict choices to the declared `reference_fact_id`, then retain only alternatives tied at the highest supplied factual-fit score. The strength-zero reference chooses the least-loaded label (minimum absolute connotation), breaking ties by lexical term. At strength `s`, selection maximizes `s × presentation_tone × connotation` within that same best-fit tie, with the reference tie-breaks for remaining ties. The primary measure is `presentation_tone × selected connotation`, in normalized alignment points `[-1,1]`. `active` is true only when the selected term differs from the reference term. Strength is a hypothetical preference control, not a probability or empirical coefficient.

**Necessary condition and scenarios.** The effect requires at least two equally fact-fitting wording alternatives attached to the same explicit fact ID. The positive fixture provides neutral and tone-aligned labels for a single fact; the supplied positive tone selects the more aligned label at strength `.8`. The boundary fixture retains a supported reference label but puts the connotative alternative under a different fact ID; the only eligible label is therefore unchanged from strength zero, so its metric is equal to baseline. Missing options for the declared fact raise `ValueError` rather than becoming a zero score.

**Scope and limitations.** This is a compact, synthetic model of one editorial choice, not a detector, population claim, diagnosis, or fitted account of psychology. Fact IDs, fit ratings, connotations, and tone are assumed inputs; the model cannot establish factual equivalence or actual audience response. Connotative word choice may be ordinary, beneficial, or stylistic and is not inherently an error or harmful practice. The example and tests are software checks only; the mechanism has not been empirically validated and no detection accuracy is claimed.
