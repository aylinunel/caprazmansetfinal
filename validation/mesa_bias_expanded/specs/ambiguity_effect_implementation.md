# Ambiguity Effect — illustrative implementation

**Process and equation.** A decision task offers two options with the same success/failure payoffs. The known option has supplied success probability `p_k`; the ambiguous option has a plausible probability interval `[p_l, p_h]`. Its reference probability is the interval midpoint `p_m = (p_l + p_h)/2`. At strength `s`, the modeled decision probability is `p_s = (1-s)p_m + s p_l`. Each option's expected utility is `p*success_payoff + (1-p)*failure_payoff`. The metric is `1` if the ambiguous option has strictly greater modeled expected utility than the known option, and `0` otherwise; ties favor the known option. The `active` flag means strength changes the chosen option relative to the midpoint reference.

**Task, units, and baseline.** The task is a single comparison of two binary-outcome options. `metric` is a binary choice indicator, not a probability or error score. Strength zero explicitly compares expected utilities using the ambiguous interval midpoint; this is a simple reference policy, not a claim of perfect rationality. Strength scales an illustrative shift toward the worst plausible probability, not an empirically estimated effect size.

**Necessary condition and scenarios.** A nonzero ambiguity interval is necessary for this mechanism to alter the probability used for the ambiguous option. The positive example has known success probability `0.55`, ambiguous interval `[0.30, 0.90]`, and payoffs `10/0`: the midpoint reference favors the ambiguous option (`6.0` vs `5.5`), but at strength `0.8` its modeled success probability is `0.36` and expected utility `3.6`, so the known option is selected. The boundary collapses the interval to `[0.60, 0.60]`; there is no unspecified probability, so strength `0.8` reproduces the midpoint reference choice and metric.

**Assumptions and limitations.** Both options share success/failure payoffs, the interval bounds are explicit inputs, the midpoint is the reference, and lower-bound weighting represents one assumed ambiguity-averse policy. Choosing conservatively can be a legitimate preference or risk-management strategy; a choice alone is not evidence of cognitive error. The model does not infer hidden beliefs, priors, or motivations, and is neither an NLP detector nor a fitted psychological account. It is explicitly hypothetical and has not been empirically validated; software tests establish only the coded synthetic behavior.
